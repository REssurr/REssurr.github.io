基于双栈中转机的开发区校园网 IPv6 免流配置以及复盘

发表于2026-11-25|更新于2026-11-25|折腾
|浏览量:

缘起

11 月 26 日《蓝色星原：旅谣》公测，25 日开预下载。启动器给出的安装包是 84.84 GB，需要 93.3 GB 空间，装完进游戏还有 14.66 GB 热更。

但是校园网额度已经超支，本月流量也所剩不多，故而需要一个能立马下载且不耗流量的方法。

学校的计费通知里有一条：校园网免费流量及超出流量均指校园网外流入量，各类校园网内服务（校内网站浏览、业务系统使用、邮箱、大工云盘等）和下一代互联网 IPv6 等均不计算流量。

也就是说，走 IPv6 的部分不算钱。目标因此明确：在 11 月 25 日当晚把游戏下完，同时让这部分流量全部走 IPv6。

折腾了一中午，总算是搞好了，踩了很多坑，所以本文同时既是技术分享也是实战复盘。读者可以先用自己的情况照着下面这张流程图判断一遍。



别人试过什么

Q：只是想让下载流量走 IPv6，公开方案都有哪些？

A： 围绕「让下载流量走 IPv6」，公开方案大致分三类：改本地 DNS 应答、改 hosts 加本地转发、用双栈服务器做隧道。

  1. 本地 DNS 改写应答。 用 Technitium DNS Server 搭本机 DNS，上游 202.118.66.6，给目标 CDN 加通配 AAAA 指向教育网节点。

  2. hosts 加本地转发。 UsbEAm：做测速优选 CDN 节点后写系统 hosts，并在本机监听 80/443 转发到选中的节点。

  3. 双栈 VPS 加隧道。 Cloudflare WARP 或者 Azure + sing-box。

下面会说明前两种方法都无法满足我的需求的原因。



我做了什么

首先确认本机确实有 IPv6 地址。

一：Technitium DNS Server，在本机改写 DNS 应答

Q：改 DNS 应答这条路能走通吗？

A： 走不通，第 1 步就断在「目标域名根本没有 AAAA 记录」上。给目标域名查 AAAA：

我逐个查了 azurpromilia.manjuu.com、webstatic.manjuu.com、plat-cdn.manjuu.com、api-grp.manjuu.com、www.manjuu.com、l.taptap.cn、d.3839.com，全部只有 A 记录。没有 AAAA 可指，改解析无从谈起。

即便有 AAAA，也还要确认这个节点真的在服务同一份文件：

能拿到 206 且证书对得上才算可用，节点必须是同一 CDN 的边缘机，证书和文件才对得上。

这个方案剩下的流程仍然值得记下来，换个游戏也许就用得上：

  1. 装 Technitium DNS Server，装完它监听本机 53 端口，管理页默认 http://localhost:5380。
  2. 在 Settings → Recursion 里把 Forwarders 设成 202.118.66.6，没配置过的查询照常转发给学校 DNS。
  3. 给目标域名建一个 Zone，加 AAAA 记录指向选定的节点。只写 AAAA 会丢掉 IPv4 退路，原来的 A 记录建议一起补进 Zone。
  4. 网卡 DNS 改成 127.0.0.1，ipconfig /flushdns。
  5. 验收：nslookup -type=AAAA 域名 应返回你写的地址；重开客户端下载，同时盯计费页面是否不动。
  6. 不用了把网卡 DNS 改回 DHCP。本机 DNS 进程一停，整台机器的解析都会断，这是这个方案最大的副作用。

二：UsbEAm 游戏下载助手，写 hosts 加本机转发

Q：那 UsbEAm 按节点转发呢？

A： 也不行，它对这个游戏的两条前提一条都不满足。

它只解决「CDN 有 IPv6 节点、但客户端按普通 DNS 拿到了 IPv4」的情况，对「CDN 根本没有 IPv6」无效。同时，蓝原启动器写死了 IP 地址，根本不会走到查 IP 这一步。我们这个游戏两条都不满足，所以没走。故而我想到了使用 TUN 来完成。

它的流程是：

  1. 同样先确认目标 CDN 有 IPv6 节点：nslookup -type=AAAA 域名。
  2. 下载 UsbEAm（dogfight360.com ）。
  3. 输入目标 CDN，进「下载」，点测速优选，挑延迟最低的节点；要免流就得挑 IPv6 地址的节点。
  4. 点应用。它在 hosts 里给域名加一行指向 127.0.0.1，同时在本机监听 80/443，把请求转发到选中的节点。退出或点还原会清掉 hosts。

三：Cloudflare WARP

Q：WARP 官方客户端有 IPv6 入口，为什么不直接用？

A： 卡在连接这一步，最后查明是到入口的 UDP 被拦。

  1. 装官方客户端。首次启动会问用途，选左侧「私密浏览」；右侧 Cloudflare One 要企业账号。
  2. 把协议和端点都固定到 IPv6：warp-cli tunnel protocol set MASQUE、warp-cli tunnel endpoint set "[2606:4700:d0::a29f:c001]:443"、warp-cli connect。
  3. 连接到外部服务器后即可开始下载。

我卡在第 3 步：状态一直是 Connecting，日志里只有

改成 warp-cli tunnel masque-options set h2-only（MASQUE over HTTP/2，理论上走 TCP）仍然卡住。期间 WARP 接管全部流量，把学校认证页 172.20.30.3 也带进了隧道，页面打不开，断开并重置端点后才恢复。

补做协议探测才看清原因：到该端点的 UDP 443 和 UDP 2408 都不通；TCP 443 通、TLS 握手也成功，但 WARP 的 CONNECT 请求没有响应。入口和协议都由 Cloudflare 决定，改不动，放弃。



只剩自建这一条路

现有方法都已失效，于是只剩最后一种：找到一个可自定义的双栈服务器，然后自己写配置。

原理

Q：自己搭，搭的到底是什么？

A： 用 sing-box 改动本地路由，将本机所有请求通过 IPv6 隧道从校园网关出去，与 Azure 建立连接，再由 Azure 服务器以 IPv4 形式下载资源，用 IPv6 隧道转发回本机。

这里有个容易漏掉的点：只用系统代理是不够的。启动器这类程序多数不读系统代理设置，只有 TUN 虚拟网卡能让它们的流量无条件进入隧道。



Azure 学生账号

Q：服务器从哪来？

A： 先用 Azure for Students 的免费额度。

  1. 打开 Azure for Students 页面，用学校邮箱（xxx@mail.dlut.edu.cn）注册。需要邮箱能收验证码；不需要信用卡。
  2. 注册完进入门户，订阅名叫「Azure for Students」。概览页有三块数字：可用额度 US$100、额度过期天数 365（到期作废、不累积，在校期间每年可重新验证身份续期）、当月成本。


Cloud Shell 怎么进、怎么选

Q：为什么不能直接在门户里点「创建虚拟机」？

A： 门户里直接点「创建虚拟机」会弹一个「选择虚拟网络配置」，要求先有资源组、虚拟网络、子网、中继命名空间，学生账号里这些都是空的，下拉全是灰的，点不动。这不是权限问题，是顺序问题：得先有网络，才能建机器。

所以改用 Cloud Shell，用命令建。

  1. 打开 https://shell.azure.com。
  2. 第一次会弹「欢迎使用 Azure Cloud Shell」，选 Bash。
  3. 接着弹「入门」，做两个选择：
    • 选 「无需存储账户」。Cloud Shell 会话是临时的，闲置约 20 分钟回收，文件清空。我们不需要它持久化任何东西，脚本和密钥都在本机。
    • 订阅下拉选「Azure for Students」。如果下拉是空的，说明登录的账号不对，重新登录。
    • 「使用现有的专用虚拟网络」不要勾。
    • 点「应用」。
  4. 等几秒，出现 azureuser@Azure:~$ 提示符，就进去了。

需要理解 Cloud Shell 是什么：它是微软临时给你的一台 Ubuntu 容器，有 az、git、curl，但没有公网 IP，不能对外提供服务，也不能在上面长期跑程序。它只是遥控器，真正要租的服务器还没建。

az 是 Azure 的命令行工具，登录状态下已用你的账号授权，等价于在门户上点鼠标。



把搭建交给 agent

接下来的操作涉及到对云端服务器的操作，让 agent 代劳就好。

把下面这段直接交给你的 agent。名字、地址、密钥、UUID 全部由它自己决定和生成，不需要你填任何值；它一次只给你一条命令，你粘贴、把输出贴回去，它判断对错再给下一步。你要做的只有三件它做不了的事：在 Azure 里登录、点一次 UAC、盯着计费面板。

接下来就可以美美下载了！



实测数据

Q：真的一点流量都没扣？

A： 预下载 84.84 GB 只记了 62 KB，热更 14.66 GB 只记了 199 KB，游戏本体合计不到 1 MB。

先说清楚：下面只有 Azure 这一台是本次真跑出来的数字，其他方案没实测过，后一张表只有定性判断。本机出口不是瓶颈：同一根网线走教育网 IPv6 直连镜像，8 MB 拿到 2.96 MB/s，从清华 TUNA 取文件到过 264 Mbps。

没走通的路线也有实测结论：Cloudflare WARP 卡在到 WARP 入口的 UDP 443 和 2408 都不通，没产生任何速度数据；usque 把 WARP 塞进 TCP 后 TLS 握手能成，但 CONNECT 请求被 RST。两条都记在「我做了什么」里。



其他双栈服务器方案对比

Q：只有 Azure 能做这件事吗？

A： 不是。凡是同时有公网 IPv4 和公网 IPv6、能连外网 443、流量够跑完这次下载的机器都行；差别在成本、IPv6 好不好拿到、以及能不能长期稳定。下表按本次调研时的情况整理。

方案 成本 IPv6 从哪来 主要难点
Azure for Students（本次采用） 0 元，$100 额度 365 天，不需要信用卡 建 VNet 时自己填一段 IPv6 前缀，再给网卡挂一个 IPv6 公网 IP 学生邮箱要能认证；eastasia 的 B 系列常缺货，得换规格或换区域
Oracle Cloud 永久免费 0 元（Always Free 额度内） VCN 先分配 IPv6 前缀，再给实例挂 IPv6 地址 注册要信用卡、风控严；免费实例可能被回收；名额紧张
GitHub 学生包 → DigitalOcean $200 额度，一年有效 创建 droplet 时勾上 IPv6 要绑信用卡；学生包通过需要时间
RackNerd 等年付小机 约 $22/年，折 13 元/月 看套餐，部分自带 IPv6 境外付款；便宜套餐不一定给 IPv6，买前要问清
腾讯云 / 阿里云轻量 约 24 元/月（学生机更低） IPv6 默认关闭，要在控制台开通并给实例分配 境内云的服务条款禁止代理用途，有封机风险；但延迟最低
家里宽带的公网 IPv6 + 旧电脑 0 元 运营商下发的 IPv6 前缀 地址会变，需要 DDNS；机器要常开；家宽上行带宽小
借同学或朋友的双栈 VPS 0 元 看对方机器是不是双栈 依赖别人；流量和合规责任在机主
Cloudflare WARP 0 元 入口有 IPv6 协议和端点都由 Cloudflare 定，改不动；本次被本校出口拦掉，失败

选型的硬条件只有四条：有公网 IPv6 入口、有公网 IPv4 出口、能对外开 TCP 443、流量够 84.84 GB。满足这四条，装机步骤完全一样。

最后选 Azure，是因为它同时满足三件事：真的 0 元且不用绑信用卡；当晚就要用，从注册到拿到机器约十五分钟；IPv6 最省事，在 VNet 里加一段前缀、给网卡挂一个 IPv6 公网 IP 就完事，不用折腾 DDNS 或运营商。代价也写清楚：额度 365 天到期作废、不累积；全月开机约 812 美元；eastasia 常缺货；跨境延迟 65106 ms，适合下载、不适合竞技。

现象 原因 处理
SkuNotAvailable 区域库存不足 换规格重试，删半成品
VM 里只有 fe80:: 网卡没有 IPv6 IP 配置，命令参数写错且 -o none 吞了错误 用 --private-ip-address-version 重建 ip-config
StandardPublicIpCannotBeAttachedToIpConfigurationWithoutSubnet ip-config 少了 --subnet 补上
netplan 报 route-metric 不一致 只改了 dhcp4 或 dhcp6 一侧 两处都写
隧道连不通、TCP 超时 NSG 没放通 443 加规则
隧道一连，校园网登录页打不开 TUN 把私有地址也接管了 加 ip_is_private 与校园网段 direct
sing-box 起不来，报 invalid character '茂' JSON 文件带 BOM 用无 BOM 的 UTF-8 写入
SSH 执行的脚本报 Invalid unit name "sing-box\r" Windows here-string 带 CR 转成 LF 或 base64


事后清理

资源用完就该删，否则额度一直在扣：az group delete -n relay-rg --yes --no-wait。这个命令是后台删除，VM 先消失（表现为公网 IP 立刻连不上），网卡、IP、VNet 随后清掉，资源组名字最后消失，几分钟到十几分钟不等。--no-wait 之后看到 az group list 里还有 relay-rg 是正常的，不要重复执行删除。

Cloudflare WARP 客户端也一并卸载了：msiexec /x 加产品码 /qn。它留下的服务 WarpJITSvc 需要单独 sc delete。



总结

Q：一中午折腾下来，得出了什么？

A： 三条路一条比一条绕，最后落到最朴素的那条：自己有一台双栈机器，把 IPv4 的下载流量装进 IPv6 隧道。

  • 本地 DNS 和 hosts 改写只对「CDN 有 IPv6 节点」的游戏有效，蓝原两条都不沾。
  • WARP 看着最省事，但入口和协议都由 Cloudflare 定，本校出口恰好把 UDP 443/2408 拦了，改不动。
  • 自建是唯一可控的：机器、端口、协议、分流规则全在自己手里。代价是要会一点命令行，以及一台服务器的钱——Azure 学生账号这次是 0 元。

最直观的一组数字：84.84 GB 预下载 + 14.66 GB 热更，计费流量一共 261 KB。免流不是什么魔法，只是把「走 IPv4 下载」换成了「走 IPv6 下载」。
